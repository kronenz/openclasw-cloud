# Operations 팀

## 미션
서비스 모니터링, 비용 관리, 장애 대응

## 소속 에이전트

| ID | 이름 | Claude Agent | 모델 | 역할 |
|----|------|-------------|------|------|
| A-OPS-001 | 데이터 분석가 | scientist | Sonnet | 사용량/비용 분석 |
| A-OPS-002 | 운영 아키텍트 | architect | Opus | 운영 의사결정 |
| A-OPS-003 | 장애 진단자 | debugger | Sonnet | 장애 원인 분석 |

## 담당 파이프라인
- **P-007: 운영 모니터링 파이프라인**

## 주요 업무

### 데이터 분석가 (A-OPS-001)
- 일일 사용량 리포트 생성 (Workers CPU, D1 쿼리, R2 전송량)
- 월간 비용 분석 및 예측
- 고객별 비용 청구 데이터 생성
- AI API 호출량/토큰 사용 통계
- 이상 패턴 탐지 (급격한 사용량 증가, 에러율 상승)

### 운영 아키텍트 (A-OPS-002)
- 스케일링 전략 수립
- 비용 최적화 방안 제안
- SLA 목표 설정 및 검토
- 아키텍처 개선 로드맵 작성
- 인시던트 대응 전략 수립

### 장애 진단자 (A-OPS-003)
- 에러 로그 분석
- 성능 병목 지점 식별
- 장애 원인 근본 분석 (RCA)
- 재발 방지 대책 수립
- platform 팀에 수정 요청

## 사용 Cloudflare 서비스
- **Workers Logs**: 전사 로그 수집
- **AI Gateway**: Claude API 호출 통계
- **Analytics**: 대시보드 메트릭
- **D1**: 운영 데이터 저장

## Human Gate 조건

**비용 임계값 초과 시 알림 및 승인 필요**

- 일일 비용 $500 초과
- 월간 비용 예측 $10,000 초과
- SLA 미달 (가용성 99.9% 미만)
- 보안 인시던트 감지

## 협업 팀
- **platform**: 장애 수정 요청
- **onboarding**: 신규 고객 리소스 산정 협력
- **integration**: API 호출량 모니터링
- **customer-success**: 고객별 사용량 리포트 제공

## 워크플로우 예시

### 일일 모니터링

```
매일 오전 9시 자동 실행
  ↓
[A-OPS-001] 전일 사용량 수집
  ↓
[A-OPS-001] 비용 계산 및 리포트 생성
  ↓
이상 패턴 감지 시
  ↓
[A-OPS-003] 원인 분석
  ↓
[A-OPS-002] 대응 방안 결정
  ↓
해당 팀에 조치 요청
```

### 장애 대응

```
알람 발생 (에러율 5% 초과)
  ↓
[A-OPS-003] 로그 분석 및 원인 파악
  ↓
[A-OPS-002] 긴급도 평가
  ↓
긴급 장애 시 platform 팀에 롤백 요청
  ↓
일반 장애 시 해당 팀에 수정 요청
  ↓
[A-OPS-003] 모니터링 및 복구 확인
  ↓
[A-OPS-003] RCA 문서 작성
  ↓
[A-OPS-002] 재발 방지 대책 수립
```

## 모니터링 대시보드
- **가용성**: 99.9% 목표 (월간)
- **응답 시간**: p95 < 500ms
- **에러율**: < 1%
- **AI API 성공률**: > 99%
- **일일 비용**: 예산 내 유지
- **Workers CPU 시간**: 무료 한도 대비 %
- **D1 쿼리 수**: 무료 한도 대비 %
- **R2 전송량**: 무료 한도 대비 %

## 알람 규칙
- **에러율 5% 초과**: 즉시 알림
- **응답 시간 p95 > 1초**: 즉시 알림
- **AI API 실패율 5% 초과**: 즉시 알림
- **일일 비용 $500 초과**: 관리자 알림
- **Workers CPU 무료 한도 80% 도달**: 경고
- **D1 쿼리 무료 한도 80% 도달**: 경고

## 비용 관리 전략
- AI API 호출 최적화 (캐싱, 배칭)
- 로그 보관 기간 제한 (30일)
- R2 파일 수명주기 정책 (90일 후 삭제)
- Workers 코드 최적화 (CPU 시간 단축)
- 고객별 요금제 티어링
